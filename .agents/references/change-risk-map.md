# Cross-boundary change-risk map

Use the narrowest row that covers the change. If a change crosses rows, combine their checks. Add a screenshot only for an affected player-visible host or phone state; protocol and lifecycle changes need behavioral proof instead.

| Seam | Authority | Invariant and blast radius | Cheapest proving check |
|---|---|---|---|
| Protocol messages | `src/shared/protocol.ts` (`ClientMsg`, `ServerMsg`, `RoomState`); `src/server/room.ts` (`parseClientMsg`, `allowed`, `onMessage`); `src/client/useRoom.ts` | Wire types, runtime parsing, role authorization, size/rate limits, and client dispatch must change together. A mismatch can disconnect every host/phone, admit role-confused traffic, or silently drop state/game messages. Game payload `g.d` stays opaque to the shell. | `npm run test:room`; for client dispatch/reconnect changes also `npm run test:client -- -t reconnect` (or the closest named case in `test/client/reconnect.test.tsx`). |
| Room lifecycle and persistence | `src/server/index.ts` (`POST /api/rooms`); `src/server/room.ts` (`provision`, `onStart`, `save`, `onAlarm`, `onHello`, `onClose`, `reclaimSeats`, `admitWaiters`, `reset`); `src/client/identity.ts`, `src/client/useRoom.ts` | One Durable Object owns a party code, durable host capability, roster/device identity, presence, scores, history, active round, and TTL. Replacement sockets must not mark the new connection away; dropped seats retain identity through grace; cold starts restore persisted state and hibernated presence. Breakage loses parties/scores, duplicates identities, strands waiters, or enables host takeover. | `npm run test:room -- -t "reconnect|persist|cold|archived|replacement|queued"`; add `npm run test:client -- -t reconnect` when browser restoration changes. |
| Game registry and dynamic imports | `src/client/games/registry.ts` (`GAMES`, `GAME_LIST`, `GameEntry`); each game's `manifest.ts`, `host.ts`, `controller.tsx`; loaders in `HostApp` and `ControllerApp` | A registry key, manifest id, host factory, and controller default export describe the same game. Both surfaces load the persisted `activeRound.gameId`; its seed identifies one round. A bad entry leaves the projector or every phone stuck in playing/loading, including after refresh. | `npm run build`; for registry/loading behavior run `npm run test:client -- -t "persisted seed|loads its controls"`. For a new game, launch it once and capture one host plus one phone screenshot. |
| Host simulation and `GameHost` | `src/client/games/registry.ts` (`HostContext`, `GameHost`); `src/client/HostApp.tsx` (`start`, RAF/session cleanup, roster effect); each game's `createHost` | The projector is the sole simulation authority. The Durable Object only routes input; games return results once, tolerate unknown/malformed payloads, receive roster versus connection changes distinctly, cap `dt`, and tear down RAF/audio/resources on round or module change. Failure can desync all players, double-score a round, crash the projector, or leak work into the next game. | Run the changed game's host test (Kart: `npm run test:client -- test/client/kart-host.test.tsx`) plus `npm run test:client -- -t "destroys the projector game|gains or loses"`. Screenshot the host only when rendering changed. |
| Controller input, coalescing, and disconnects | `src/client/useRoom.ts` (`sendGame`); each game's controller (Kart: `SEND_HZ`, held-pointer cleanup); `src/server/room.ts` (`g` routing and message budgets); `HostApp` roster effect; each host's `onInput`/`onConnectionChange` | Phones send bounded game input; continuous controls coalesce at a rate below server budgets, transient actions are consumed once, and blur/visibility/unmount/disconnect neutralize held state without deleting a durable seat. Breakage causes flooding, stuck movement, lost taps, unfair control, or disconnect storms across a full room. | Kart: `npm run test:client -- test/client/kart-controller.test.tsx test/client/kart-host.test.tsx`; rate/routing changes: `npm run test:room -- -t "20 Hz|ordinary controller input|hibernated controllers"`. |
| Audio lifecycle | `src/client/audio.ts` (shared context, bus, cache, mute/unlock); each game's audio module (Kart: `KartSound`); host/controller construction and cleanup | Audio unlocks from a user gesture, respects the persistent master mute, remains optional, preloads/caches assets, caps voices, and disconnects/stops sources on teardown. Host cues are shared; phone cues are player-specific. Failure can block play, leak loops between games, multiply sound, or produce silence/harsh overlap. | Run the changed audio test (Kart: `npm run test:client -- test/client/kart-sound.test.tsx`); manually tap sound once on the affected surface only when gesture or mute wiring changed. |
| Standings and history | `src/shared/protocol.ts` (`RoundResult`, `RoundRecord`, `leaderboard`, `MAX_HISTORY`); `src/server/room.ts` (`roundOver`, `backToLobby`, `resetParty`, `validResults`); `HostApp.tsx` (`Standings`, `RoundStrip`); phone standings in `ControllerApp.tsx` | Only the current host may close an active round; results contain known players once each; totals update once; history is capped; ties share place; canceling play records nothing and rolls the round back; reset keeps room/seats but clears tournament state. Breakage corrupts the durable party record and every host/phone ranking. | `npm run test:room -- -t "round results|in-progress round"`; for display changes, capture one standings screenshot on the affected surface. `resetParty` has no focused automated test yet, so exercise the Reset journey when that path changes. |

After any public type or cross-row change, finish with `npm run verify`.
